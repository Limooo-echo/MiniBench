# 四维评分：实施与验收清单

详细定义见 [评分设计讲解](scoring-design.md)。本清单记录已交付内容和当前验收结果。测试通过表示实现符合已验证规则，不代表现有实验数据已经足够发布完整四维分数。

## 交付内容

- [x] 独立离线命令：`minibench score-suite --manifest <实验清单> --weights <评分配置> --output <输出目录>`。
- [x] 输入原题、逐题答案或轨迹，以及可核实的实验来源；不调用模型、不自动补跑。
- [x] 为 Zebra、一笔画、象棋、普通麻将、单人麻将和麻将规则任务读取原始证据，统一给出完整成功、部分分、辅助指标与缺失原因。
- [x] 按“重复运行 → 同组题目 → 难度或历史长度 → 题型或规则 → 输入或记忆模式”汇总，再应用四维任务权重。
- [x] 同时报告主分数、只看成功的严格分数、固定权重覆盖率、题目贡献、敏感性结果与可计算的不确定性。
- [x] 独立生成 `scores.json`、`task_scores.csv`、`item_scores.jsonl`、`report.md` 和符合覆盖条件的雷达图，记录评分版本和输入来源。
- [x] 保持原题、提示词、现有评分语义和原实验结果不变；输出目录必须不存在或为空，不覆盖已有报告。

## 关键约束

- [x] 首版不追加问题，不设计新题，不改变现有实验协议。
- [x] 四维为直接解题、规则变化、历史信息、图像输入；不再合成一个总分。
- [x] 单题先算 `Y + (1 - Y) × 0.25 × P`，再平均。失败题的部分分最高为 0.25。
- [x] 部分分必须来自已有答案；环境中的真实状态不是模型还原的状态。
- [x] 缺失、评分器故障和外部服务故障不补零；可判定的模型错误按失败评分。
- [x] 缺少正权重数据时不为某个架构临时重新分配权重，不发布该维度正式分数。
- [x] 不混合基础模型、协议、题目版本或无法核实来源的实验。当前配置文件不是旧运行配置的证据。
- [x] 架构使用各自默认配置，成本并列展示；不声称排除了计算资源差异。

## 已验证的场景

- [x] 权重每列和为 1；有效分数范围正确；文稿中的手算样例一致。
- [x] 单题先计算再平均，不能先平均成功率与部分分后套公式。
- [x] Zebra 每题等权，不因格子更多而增加题目权重。
- [x] 一笔画历史使用剩余图，处理撤销、平行边、无解、零剩余边及无法续成完整答案的路径。
- [x] 麻将集合评分处理漏报、多报、重复牌、非法弃牌、未返回字段及零分母。
- [x] 象棋合法但目标未完成不能得到主分的过程奖励；引擎错误不能当作评价损失为零。
- [x] 标准规则和文字、完整状态等对照不混入对应主分。
- [x] 长对局、重复次数多的题不自动获得更大权重。
- [x] 缺失结果不补零、不重新归一化；严格分数可独立计算时应保留。
- [x] 不同模型、协议或原题版本不混成正式比较。
- [x] 同源变体、模式和重复运行共同抽样；架构使用相同抽样；不足以估计时明确标记。
- [x] 相同输入生成相同评分内容；输入文件不被修改；运行过程无模型调用。

## 验收标准

每个正式维度分数都能追溯到原题、已有答案和明确公式。每个暂时不能发布的分数都说明缺少哪项证据。雷达图仅为四维主分完整的架构绘制完整多边形。

本地结果核对：当前工作区定位 9 组逐题记录，共 580 条，原 predictions 文件评分前后的 SHA-256 一致。旧一笔画题目 ID / 图像模式未强行映射至当前版本；其他位置的试运行结果仍待定位。已用文稿演示数值验证四维向量，并实际渲染雷达图；演示图不作为实验结果。
